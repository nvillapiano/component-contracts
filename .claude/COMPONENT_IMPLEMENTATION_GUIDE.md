# Component Implementation Guide

## Token Hierarchy Rule (Critical)

**All component implementations MUST reference Tier 3 (Component) tokens, never Tier 1 or Tier 2 tokens.**

### The Three-Tier System

```
Tier 1: Primitives        → /packages/tokens/src/primitive/*.tokens.json
        Raw values only (colors, sizes, durations)

Tier 2: Semantic           → /packages/tokens/src/semantic/semantic.tokens.json
        Semantic aliases (brand, error, text.primary, surface, etc.)

Tier 3: Component          → /packages/tokens/src/component/{id}.tokens.json
        Component-specific tokens (button.fill.brand, accordion.text.trigger, etc.)
```

### Why This Matters

- **Single Source of Truth**: The contract defines what tokens a component uses
- **Maintainability**: Changing a component's design only requires updating its token file + CSS
- **Consistency**: All implementations (React, Web Components, iOS, Android) reference the same tokens
- **Traceability**: The CSS directly maps to the contract specification

### Example: WRONG ❌

```css
/* ❌ BAD: Directly using semantic tokens */
.ds-button {
  background-color: var(--ds-brand-500);      /* Tier 2 - semantic */
  color: var(--ds-neutral-0);                  /* Tier 2 - semantic */
  border-color: var(--ds-error-500);          /* Tier 2 - semantic */
}
```

### Example: CORRECT ✅

```css
/* ✅ GOOD: Using component tokens */
.ds-button {
  background-color: var(--ds-button-fill-brand);      /* Tier 3 - component */
  color: var(--ds-button-text-inverse);               /* Tier 3 - component */
  border-color: var(--ds-button-fill-brand);          /* Tier 3 - component */
}
```

## Component Implementation Checklist

When implementing a new component or updating an existing one:

- [ ] **Contract exists** at `packages/contracts/src/{id}.contract.json`
- [ ] **Token file exists** at `packages/tokens/src/component/{id}.tokens.json`
- [ ] **CSS uses ONLY component tokens**, never semantic/primitive tokens
  - Check: `grep "var(--ds-" component.css | grep -v "var(--ds-{id}-"` should be empty
- [ ] **All token references in CSS are defined** in the component token file
- [ ] **Structural tokens are acceptable**: `--ds-space-*`, `--ds-radius-*`, `--ds-duration-*`, etc.
  - These are reusable across all components
- [ ] **System tokens are acceptable**: `--ds-focus-ring-offset`, `--ds-surface-default`
  - These are global system constraints, not design decisions
- [ ] **Semantic color/text tokens are NOT acceptable**: `--ds-brand-*`, `--ds-error-*`, `--ds-neutral-*`, `--ds-text-*`
  - Create component-specific tokens in the component token file instead

## CSS File Template

Every component CSS file should start with this comment:

```css
/* ─── {Component Name} ────────────────────────────────────────────────────────
   All values reference CSS custom properties generated by @ds/tokens.
   IMPORTANT: Use ONLY tokens from /packages/tokens/src/component/{id}.tokens.json
   Never use semantic tokens (--ds-brand-*, --ds-neutral-*, etc.) or primitives directly.
   See: .claude/COMPONENT_IMPLEMENTATION_GUIDE.md
   ─────────────────────────────────────────────────────────────────────────── */
```

## Validation Script

To audit all component CSS files for token usage violations:

```bash
cd apps/web
find . -name "*.css" -path "*/components/*" -o -path "*/molecules/*" | while read f; do
  echo "=== $f ==="
  # Show semantic tokens that should be component tokens
  grep -o "var(--ds-brand-\|var(--ds-error-\|var(--ds-neutral-\|var(--ds-text-" "$f" | sort -u
done
```

## Questions?

If you're unsure whether a token should be in the component token file, ask:

1. Is this a design decision specific to this component? → Use component token
2. Is this a structural concern (spacing, radius, duration)? → OK to use structural token
3. Is this a system constraint (focus ring)? → OK to use system token
4. Is this a reusable semantic concept (brand color)? → Create component token that aliases it

## Examples

### Button
- ✅ `--ds-button-fill-brand` → `{brand.600}` (component decision: which shade of brand?)
- ✅ `--ds-button-text-inverse` → `{neutral.0}` (component decision: what text color on dark?)
- ❌ `--ds-brand-500` (use the button token instead)

### Accordion
- ✅ `--ds-accordion-border-item` → `{border.default}` (component decision: what border style?)
- ✅ `--ds-accordion-text-trigger` → `{text.primary}` (component decision: what text color?)
- ❌ `--ds-neutral-200` (use the accordion token instead)

### Text Input
- ✅ `--ds-text-input-border-focus` → `{brand.500}` (component decision: focus indicator)
- ✅ `--ds-text-input-background` → `{neutral.50}` (component decision: input surface)
- ❌ `--ds-neutral-50` (use the text-input token instead)
